初始化建置流程解析

參考 gas-school-lunch-management-system 的實作原理，探討無 npm 替代方案

1 什麼是初始化建置流程？

GAS Web App 不像傳統後端有「執行環境初始化」的概念——部署上去就開機了。但實際營運系統需要資料庫結構（工作表）、系統參數、預設資料、管理員帳號等一次性設定，這就是「初始化建置流程」要解決的問題。

本地端自動化

從原始碼到線上部署的一鍵流程：clasp 授權、建立專案、上傳、部署

資料庫初始化

建立 29 張工作表、寫入 SystemConfig、預設補助規則、管理員帳號

冪等設計

工作表已存在則跳過、欄位缺少才補齊，重複執行不破壞既有資料

2 兩階段流程總覽

1 本地 CLI 自動化

終端機執行 npm run setup

→ 檢查 Node.js ≥ v20
→ clasp 授權登入（未登入時開啟瀏覽器）
→ clasp create 自動建立 GAS 專案
→ 寫入 .clasp.json
→ clasp push --force 上傳原始碼
→ clasp version 建立版本號
→ clasp deploy 部署取得 Web App URL
→ 存入 .deploy/uat.json 固定部署 ID
2 網頁引導精靈

開啟 Web App URL，同意授權後進入

→ 選擇環境（UAT / PRODUCTION）
→ 填寫學校名稱、管理員姓名
→ 點擊「開始一鍵初始化」
→ 建立 29 張工作表（缺則建、缺欄位則補）
→ 寫入 SystemConfig 預設參數
→ 建立補助身分類別與規則（草案）
→ 註冊第一位 system_admin
→ 建立 Drive 歸檔資料夾 + Audit Log

3 deploy.sh 深度解析

這是整個流程的核心指令稿，僅仰賴 bash + Node.js + clasp，由 npm run setup 觸發。

區段 實作方式 關鍵細節
環境檢查 node -v | cut -d'v' -f2 主版本號 ≥ 20，不符則 exit 1
clasp 授權 npx clasp status → npx clasp login 未授權時自動開啟瀏覽器；無 headless 模式，需人工操作
Script ID 判定 參數 → .clasp.json → 自動建立 三種來源依序嘗試，最後手段才 clasp create
自動建立專案 npx clasp create --title "..." --type webapp 在 temp 目錄執行避免汙染本地；若 API 未啟用則導引使用者開啟
寫入設定檔 cat heredoc → .clasp.json + .claspignore .claspignore 只允許 .gs、.html、appsscript.json
上傳與版本 clasp push --force + clasp version --force 覆蓋遠端；version 用 regex 解析版本號
部署 clasp deploy / clasp redeploy .deploy/{uat,production}.json 保存 deploymentId，確保 URL 固定
PRODUCTION 防護 read -p 確認字串 必須輸入 "DEPLOY TO PRODUCTION" 才能繼續
關鍵洞察：deploy.sh 雖然是透過 npm run setup 觸發，但它本質上只依賴 node + npx（clasp 由 npx 動態下載），即使沒有 package.json 也能運作。真正的自動化邏輯全在 bash 指令稿中。

4 SetupService.gs 深度解析

4.1 工作表 Schema 定義

以常數物件定義全部 29 張工作表的預期欄位：

var DATABASE_SCHEMAS = {
  'SystemConfig': ['config_key', 'config_value', 'description', 'updated_at', 'updated_by'],
  'Users':         ['user_id', 'email', 'name', 'role', 'class_id', 'enabled', 'created_at', 'updated_at'],
  'Classes':       ['class_id', 'school_year', 'grade', 'class_name', ...],
  'Students':      ['student_id', 'student_number', 'school_year', 'class_id', ...],
  'SubsidyRules':  ['rule_id', 'subsidy_category_id', 'funding_source', ...],
  // ... 共 29 張
};
設計要點：把 schema 當作「規範」而不是「指令」。初始化時比對既有工作表，缺失才建立；欄位不足才補。這樣每次執行都是安全的。

4.2 runInitializeWizard()

這是第二階段的核心，狀態機驅動的冪等初始化函式：

1
權限檢查：僅 system_admin 或 bootstrapper 可執行
2
逐表建立：遍歷 DATABASE_SCHEMAS，呼叫 SpreadsheetApp.insertSheet() + sheet.appendRow(headers)，設定凍結首列 + 粗體表頭
3
寫入 SystemConfig：檢查是否已存在，只新增不覆蓋。包含 25 項系統設定（學校名稱、餐費、四捨五入規則等）
4
預設資料：6 種補助身分類別、6 條補助規則（enabled: false 草案狀態）、第一位 system_admin
5
Drive 與日誌：建立學年度子資料夾、寫入 Audit Log

4.3 getSystemStatus() — 狀態檢查

在引導精靈顯示前先執行，判斷系統處於哪個階段：

檢查項目 判定方式 對應的 statusLevel
isInitialized 29 張工作表全部存在且欄位正確 healthy
sheetsCount 比對 current 與 expected warning
requiredConfigComplete SystemConfig 中的必填參數是否都存在 warning
timezoneCheck Script 與 Spreadsheet 時區均為 Asia/Taipei warning
folderStatus 報表資料夾可讀可寫 blocking
SchoolDays 重複 檢查是否有重複日期 blocking

6 無 npm 的替代實作方案

這個專案目前沒有 package.json，以下分析五種不需要 npm 的初始化建置方式：

方案 A：純 bash + 全域 clasp

最接近原作的精簡版

推薦 
#!/usr/bin/env bash
# setup.sh — 不需 npm，只要 node 有裝 clasp
set -e

# 檢查 clasp
if ! command -v clasp > /dev/null; then
  echo "請先安裝 clasp: npm install -g @google/clasp"
  exit 1
fi

# 建立專案（若無 .clasp.json）
if [ ! -f ".clasp.json" ] || [ "$1" = "--create" ]; then
  clasp create "專案名稱" --type webapp
fi

clasp push --force
VERSION=$(clasp version "auto" | grep -oP 'Version \K\d+')
clasp deploy -V "$VERSION" -d "deploy"
echo "部署完成"
優點 不需套件管理器，指令稿不到 20 行；clasp 全域安裝一次就好
注意 需手動安裝 clasp（npm install -g @google/clasp），但只需做一次

方案 B：GAS 自體初始化

完全不需要本地端工具

最簡單

使用者只需手動做一次：

  1. 建立 Google 試算表
  2. 開啟「擴充功能 → Apps Script」，貼入 Code.js 與 index.html
  3. 部署為 Web App
  4. 開啟網址，系統偵測到尚未初始化 → 自動跳轉到「初始化精靈」
// Code.js
function doGet() {
  var status = getSystemStatus();  // 類似 SetupService.getSystemStatus
  var template = HtmlService.createTemplateFromFile('index');
  template.needsSetup = !status.isInitialized;
  return template.evaluate();
}
優點 零本地依賴，使用者只需要瀏覽器
注意 需手動操作 GAS 編輯器；版本控制需在 GAS 編輯器中管理

方案 C：Google Sheets 觸發初始化

以試算表作為初始化入口

低摩擦

利用 Google Sheets 的容器綁定特性：

  1. 使用者複製一份「試算表範本.xlsx」到自己的 Google Drive
  2. 開啟「擴充功能 → Apps Script」→ GAS 已自動綁定該試算表
  3. 按一下自訂選單中的「初始化系統」
// Code.js
function onOpen() {
  SpreadsheetApp.getUi()
    .createMenu('🗄️ 系統管理')
    .addItem('🏗️ 初始化系統', 'showSetupWizard')
    .addToUi();
}

function showSetupWizard() {
  var html = HtmlService.createHtmlOutputFromFile('SetupWizard')
    .setWidth(800).setHeight(600);
  SpreadsheetApp.getUi().showModalDialog(html, '初始化精靈');
}
優點 直覺、試算表即入口，綁定後 GAS 自動取得試算表存取權
注意 需提供試算表範本供使用者複製

方案 D：GitHub Actions CI/CD

推送即部署，完全自動化

雲端

在 GitHub 上設定 Actions，每次 push 到 main 就自動部署：

# .github/workflows/deploy.yml
name: Deploy to GAS
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm install -g @google/clasp
      - run: echo "$CLASP_TOKEN" > ~/.clasprc.json
        env:
          CLASP_TOKEN: ${{ secrets.CLASP_TOKEN }}
      - run: clasp push --force
      - run: clasp deploy -d "CI deploy"
優點 零本地操作，但首次仍需要手動初始化資料庫
注意 需要一組 clasp token（~/.clasprc.json）存入 GitHub Secrets

方案 E：bootstrap API（純自部署）

最簡版，適用於單一管理者

極簡

完全捨棄本地工具，在 Web App 中內建完整 bootstrap 能力：

  1. 使用者部署 Web App（需手動設定試算表 ID 到 Script Properties）
  2. 第一次開啟時，後端偵測到無工作表 → 自動建立
  3. 自動在 Drive 建立設定檔資料夾、寫入預設參數
  4. 導引使用者填入 Client ID 等必要參數
這其實就是 SetupService.gs 的 bootstrapSystem()——它連試算表和 Drive 資料夾都是自動建立，完全不需手動建立任何 Google 資源。

7 對本專案的建議

考量 gas-auth-spa-template 目前的狀況（無 package.json、僅有 Code.js + index.html、使用 Google Sheets 作為資料庫），最適合的方案組合是：

階段一：自體初始化（方案 B）

在 Code.js 中加入初始化邏輯，讓 Web App 第一次開啟時自動建立「網站參數設定」與「帳號管理」工作表。這已經是部分實作了（getWebsiteParameter 有 lazy init），只需補上網頁引導精靈。

階段二：setup.sh（方案 A）

提供一個 bash script 讓有 clasp 的使用者可以一鍵部署。即使專案沒有 package.json，只要使用者全域裝了 clasp，就能用 bash setup.sh 完成部署。

核心架構 — 加入後端初始化服務：

// Code.js 新增模組
var SetupService = (function() {
  var SCHEMAS = {
    '網站參數設定': ['參數項目', '參數內容', '參數說明'],
    '帳號管理':     ['Email', '姓名', '人員編號', '部門單位', '角色', '狀態', '備註']
  };

  function getSystemStatus() {
    // 回傳 { isInitialized, sheetsStatus, warnings, blockingIssues }
  }

  function runInitializeWizard(settings) {
    // 建立工作表、寫入預設值、註冊管理員
  }

  return { getSystemStatus: getSystemStatus, runInitializeWizard: runInitializeWizard };
})();
